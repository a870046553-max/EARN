# 分步建模操作规范

## 1. 登记原件

原件只读，保存文件名、哈希、单位字段、图框文字和版本。DXF 来自同一 DWG 的副本导出。尺寸文字、尺寸实体的几何测量值和直接量取源几何必须分别记录，文字可能被覆盖。单位为 mm 不等于纸面几何比例为 1:1。

## 2. 核对三视图

- 先以 A/B/C/D 标识纸面区域，确认投影符号及排列；没有足够依据时使用显式坐标映射，不靠位置猜方向。
- 为各正投影视图记录水平轴、竖直轴、视线方向。至少覆盖三个相互正交的方向；轴测图仅作空间关系辅助。
- 选择贯通孔、圆柱外缘、台阶、耳片等可辨特征，跨视图对应实体编号和位置。检查长对正、高平齐、宽相等；先核对比例、旋转及镜像。
- 区分外轮廓、实际棱边、相切边界、隐藏线、中心线、尺寸线、剖面线、曲面接缝。图层及线型不能单独证明语义。光滑面轮廓随视向变化，不一定是实体边。
- 任何用于建模的尺寸，都应记录来源：图上尺寸、源几何量取、实测或明确假设。源几何需结合确认后的比例和投影方向解释。
- 未表达的内腔、壁厚、孔是否贯穿、多个件的装配关系单独列疑问。前一错误模型不作为证据。

评审 JSON 最少包含：

```json
{
  "status":"confirmed",
  "reviewer":"实际评审人",
  "reviewed_at":"实际评审时间",
  "unit":{"name":"mm","evidence":"实际单位依据"},
  "scale":{"geometry_to_mm":1,"evidence":"实际比例核对依据"},
  "projection":{"system":"explicit_mapping","evidence":"实际视向判定依据"},
  "views":[
    {"region":"A","horizontal":"+X","vertical":"+Y","look_direction":"-Z","evidence":"仅格式示例，不是2222的判定"}
  ],
  "correspondences":[
    {"meaning":"同一特征的实际对应含义","refs":[{"view":"A","entity_id":"真实编号"},{"view":"B","entity_id":"真实编号"}]}
  ],
  "dimensions":[{"name":"实际尺寸名称","value_mm":10,"source_type":"source_geometry","evidence":"真实实体编号、量取方式及比例"}],
  "line_roles":[{"entity_ids":["真实编号"],"meaning":"实际线条语义"}],
  "unknowns":["不影响本阶段的未表达信息及处理边界"],
  "blocking_unknowns":[]
}
```

这是字段格式，**不能照抄为已确认内容**。还需保留模板 source_sha256，提供三个正交视向与至少两组跨视图对应。`import-review` 检查完整性及引用是否存在，但无法证明判断正确。

## 3. 拆解造型，准备阶段计划

主体先抓真实基准和大形。规则部分用拉伸、旋转等；变化截面按边界、导向和连续性选择扫描/放样/曲面。需要布尔时建立独立工具体，注明并集、差集、交集的目的，记录实际体名；不将视图轮廓直接解释成截面。

先写预期体积、包络、实体数，再执行。建模尺度、坐标、穿透方向与前述视图映射一致。命令模板只是执行手段，不决定建模逻辑。

阶段计划示例字段：

```json
{
  "stage_id":"01-base",
  "review_sha256":"由当前已接受review.json计算的摘要",
  "purpose":"实际几何目的",
  "evidence_refs":["对应源实体与尺寸记录"],
  "predecessor":null,
  "steps":[{"method":"add_box","args":{"width_mm":20,"height_mm":20,"depth_mm":10,"name":"主体示例"}}],
  "expected":{"solid_count":1,"volume_mm3_range":[3999.9,4000.1],"size_mm_ranges":[[19.99,20.01],[19.99,20.01],[9.99,10.01]]},
  "projection_check":"描述从阶段模型提取哪些投影/截面与哪些源实体对应"
}
```

这只是接口示例，不是 2222 的建模计划。布尔操作用 `combine_bodies`，独立实体可用 `add_extruded_profile_on_plane` 且 `merge:false` 建立。体名称必须从模型实际 `list_bodies` 查询，不凭假设。

## 4. 执行与回看

每阶段创建独立模型文件，逐条执行后重建、Check2、测量体积及包络，保存前/右/上/轴测截图。截图视向是模型坐标视向，要按读图映射解释，不能自动等同于纸面 A/B/C。

通过数值检查后，状态为“待造型评审”。评审人以模型实际投影或剖面检查轮廓、孔槽位置、遮挡、厚度与过渡。正确后，在该阶段 `result.json` 的 `shape_review` 中记录 `status:accepted`、`reviewer`、`evidence`、`reviewed_at`。下一阶段绑定这一前序阶段。不能用原图曲线冒充模型验证曲线。

失败保存错误与中间记录，诊断后新建阶段编号或更正方案；不要反复尝试未知参数。细节圆角要有来源，不能靠大圆角掩盖主体轮廓错误。

## 5. 节省调用

- 首次解析后按哈希缓存；直接在网页放大和点选实体，避免反复输出数千行几何。
- 只传当前阶段的尺寸表、差异及少数关键截图给 AI。
- CAD 运算、文件检查、日志和进度生成使用本地脚本，无模型推理调用。
- 不开启循环截图、自动 AI 重试或多个付费助手。
- 使用 GitHub 记录代码和规则的变更；网页入口查看实际进度。GitHub 不代替读图判断。
